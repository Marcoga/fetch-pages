Climbing Lab Database Schema

training_sessions
id (PRIMARY KEY)
date (UNIQUE)
climber (Marco/Giselle/Both)
notes (TEXT)
analyses
id (PRIMARY KEY)
session_id (FOREIGN KEY)
model (fetch/gemini/opus)
url (UNIQUE)
logs
id (PRIMARY KEY)
content (TEXT)
created_at (DATETIME)

Relation: Each training session can have multiple analyses (e.g., one from Fetch, one from Gemini, and one from Opus).
