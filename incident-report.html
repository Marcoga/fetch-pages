Incident Review: Search Hang

Date: February 19, 2026
Time: 19:43 - 19:53 UTC
Impact: Agent unresponsive for ~5 minutes; manual restart required (SIGTERM).

Executive Summary

The agent became unresponsive after receiving an image message at 19:43 UTC. Analysis indicates the media tool (specifically image understanding via Gemini CLI) hung indefinitely. Due to the serialized nature of the agent loop, subsequent messages were blocked. The hang persisted until the user manually terminated the process at 19:48 UTC. A second hang occurred shortly after restart (19:53 UTC) likely due to retrying the same operation or similar conditions.

Timeline

  • 19:43:33 UTC - Inbound Image: User sent a JPEG image (108 chars metadata).
  • 19:43:58 UTC - Inbound Text: User sent a follow-up text message (101 chars).
  • 19:44:xx UTC - Processing Started: Agent began processing (typing indicator activated).
  • 19:46:29 UTC - Typing Timeout: Typing indicator TTL reached (2 minutes), confirming the agent was stuck in a long-running operation.
  • 19:48:41 UTC - User Follow-up: User sent another message, likely due to lack of response.
  • 19:48:57 UTC - SIGTERM: User manually killed the process to restore service.
  • 19:51:31 UTC - Recurrence: Agent hung again after restart, leading to another SIGTERM at 19:53:26 UTC.

Root Cause Analysis

1. Tool Hang

The primary cause was a hang in the image processing tool. The configuration relies on auto-detected defaults for media understanding (Gemini CLI), which lacks an explicit timeout in the user's openclaw.json. The default behavior allowed the tool to hang indefinitely (or beyond the 2-minute typing timeout).

2. Concurrency Blocking

OpenClaw's agent loop serializes runs per session to maintain consistency. When the image processing hung, the subsequent text messages were queued behind it, causing the perceived "Search Hang" where the agent ignored new inputs.

3. Missing Configuration

Review of openclaw.json reveals:

  • Missing tools.media configuration (relying on defaults).
  • Missing tools.web.search configuration (Brave API key not found in env). If the user intended to search based on the image, the agent might have attempted a fallback (like Gemini grounding) which also hung, or the hang was purely in the image analysis phase.

Recommendations

1. Configure Explicit Timeouts

Add a tools.media block to openclaw.json to enforce a strict timeout on media operations. This prevents a single tool from hanging the entire agent.

"tools": {
  "media": {
    "image": {
      "timeoutSeconds": 60
    }
  }
}

2. Enable Web Search (Optional)

If web search capability is desired, configure the Brave Search API key. This ensures the web_search tool functions correctly and fails fast if the API is unreachable, rather than hanging.

"tools": {
  "web": {
    "search": {
      "enabled": true,
      "apiKey": "YOUR_BRAVE_API_KEY",
      "timeoutSeconds": 30
    }
  }
}

3. Review CLI Stability

The hang likely occurred in the google-gemini-cli execution. Ensure the CLI is up-to-date and stable. Consider switching to a direct API provider (e.g., OpenAI or Anthropic) for media understanding if the CLI remains unstable.
